# 13 — Web UI

The web client is `../opencode/packages/app`: SolidJS + Vite 8 + Tailwind 4 +
`@tanstack/solid-query` + `solid-js/store`. `packages/web` is the docs site and
is not served. The Rust server serves the built app from the same origin.

## Serving contract

- `GET /` and every non-API GET/HEAD → `index.html`, `no-cache`.
- `_assets/**`, `icons/**` → immutable 1-year cache; missing → 404 `no-store`.
- `/api*`, `/auth/*`, `/openapi.json` never fall back to HTML.
- `sw.js`, `registerSW.js` → `no-cache`.
- Non-GET/HEAD on a page path → 405.
- `X-Content-Type-Options: nosniff` always; no CSP header is emitted yet (the
  build does not write `web/csp.json`).
- `web/dist` is read from disk per request (`OC_WEB_DIST` / `--web-dist`; default
  `<cwd>/web/dist`). It is not embedded with `rust-embed`, so replacing the
  directory takes effect without a restart.
- Static assets are negotiated with `accept-encoding`: gzip/brotli above 1 KiB,
  `content-encoding` on the wire, and `Vary: Accept-Encoding` on every static
  response (compressed or identity) so caches do not pin one variant. SSE is
  never compressed or buffered: the compression layer wraps only the static
  fallback router, not `/api`.
- `*.map` is not part of the shipped dist (Sentry-only upload artifacts) and is
  never served: any `*.map` request answers 404 `no-store`, and the build fails
  if one is present.

## Build pipeline (vendored, reproducible)

`opencode-rust/ui/` contains:

```
vendor/opencode/       # editable MIT source snapshot (app + workspace closure)
UPSTREAM               # version/provenance of the snapshot
patches/               # provenance of the nine UI patches (already applied)
build.ps1 / build.sh   # frozen install, vite build, copy + verify dist
verify-dist.mjs        # fails on placeholders/missing assets
```

`ui/vendor/opencode/packages/app` is the frontend source. Edit
`packages/app/index.html` for the HTML entry, or `src/**`/`packages/ui`/
`packages/session-ui` for TSX/CSS, then run `./build.ps1` (PowerShell) or
`./build.sh` (Git Bash). The script runs `bun install --frozen-lockfile`, builds
`@opencode/app`, replaces `opencode-rust/web/dist`, and verifies that
`index.html` has no `%OPENCODE_` placeholders and that every referenced asset
exists. `web/dist` is served from disk by `oc-server`; no Rust rebuild or
embedding is involved. `OC_UPSTREAM` can point at a different **already
patched** checkout.

The nine patches under `ui/patches` are kept for provenance and re-vendoring;
the vendored tree already contains them, so the build does not apply patches
(and is therefore idempotent). Updating the snapshot is documented in
[`ui/vendor/README.md`](../ui/vendor/README.md).

## Session and agent UI

- **Subagent tree**: a collapsible panel in the session header showing
  parent/children/siblings with agent, model, depth, lane, state and elapsed
  time. Elapsed is wall time from the child's `time.created` to `time.idle`
  (or now while busy), ticked once per second only while the panel is open and
  a node is busy (`session/agent-panels/subagent-tree.tsx:130-144`); there is no
  expectation budget on the row. Clicking a node navigates to that session
  (existing child route + breadcrumb). The tree refetches on `session.created`,
  `session.deleted`, `session.updated`, `session.renamed`, `session.status` and
  `session.execution.*` SSE events through a 600 ms trailing debounce
  (`agent-queries.ts:84-120`), not a background poll, and `session.created`
  with a `parentID` invalidates `session.family:<parentID>` in the client store
  so newly spawned subagents appear without an F5 refresh.
  The panel is the answer to "where are all my subagents", so it follows three
  rules that the mobile drawer and the desktop header share
  (`session/agent-panels/subagent-tree-state.ts`):

  - The **count excludes the root** session: the header pill, the busy/failed/
    completed pills and the "All (N)" filter all go through `subagentCount` /
    `subagentCountIn`, i.e. every node except the tree's `root`, and the mobile
    badge uses the same helpers so the two surfaces cannot disagree. The rows
    still list every node, including the routed session marked "current" —
    only the counts drop the root.
  - The list is **expanded by default on every surface**, not just the desktop
    header: `readSubagentTreeCollapsed()` returns open when no preference is
    stored. It is not a desktop/mobile branch — on mobile the same panel renders
    inline inside the agent drawer's sheet, which never collapses. An explicit
    collapse is remembered under `opencode.session.subagent-tree.v3.collapsed`,
    and the previous `…v2.collapsed` value is still read, so a reader who closed
    the strip stays closed across the version bump.
  - A query failure is **rendered as a reason, not as nothing**
    (`data-component="session-agent-tree-error"`). `agent-queries.ts` now treats
    HTTP 401/403 like 503 and returns unavailable-with-reason instead of
    throwing, so an auth-gated server shows the localized
    `session.agentPanels.tree.unavailable` line (en + tr) rather than an empty
    strip; the raw server reason is exposed only as `data-detail`, so no
    untranslated string is printed into a localized surface. "Nothing to show"
    and "could not ask" stay distinguishable.
- **Model & variant notices**: `"default"`, `""`, and `undefined` variants are
  canonicalized to `undefined` across the composer selection, handoff notices,
  store event handler, and timeline projection so repeating the default variant
  never emits or renders redundant `"Switched variant to Default"` notices.
- **Sibling chat**: a drawer on a child session, listing messages from siblings
  and a composer that calls `POST /api/experimental/subagent/:SID/message`.
  It is visually distinct from user messages (peer badge) and it is no longer
  the only place a peer message appears: delivered and queued peer rows render
  in the **main timeline** of every session, root and child.

## Peer messages in the timeline

A peer message is a conversation turn, not a notice, so it renders where the
reader already is (`session-ui/src/timeline/projection.ts`,
`session-timeline-row.tsx` `PeerMessage`).

- A peer row opens a turn (`turn.user ?? turn.peer`), so an answer reads as a
  reply rather than as a floating system line.
- **Q&A pairing.** `metadata.replyTo` (set by `talk`'s `reply_to`) links an
  answer to the question it answers: the projection inserts the answer directly
  after that question even when the answer arrives first. When `replyTo` is
  absent the answer keeps its chronological/positional place, which is the
  fallback for rows written before the field existed.
- **Queued peer rows** carry an inbox status and offer **Send now** (re-admit as
  `steer`) and **Cancel**. They render in the timeline for root and child
  sessions alike; the composer's queue strip is no longer the only surface for
  them, and it no longer renders a peer row in a child session.
- **Cancelled peer rows stay visible** with a `Cancelled` chip: cancellation
  marks `metadata.cancelled` instead of deleting the row, so history does not
  silently lose a message that was never answered.
- Peer rows are attributed by `metadata.from`/`metadata.agent` and labelled by
  `kind` (`note|question|answer`); a row sent by the reader is labelled "you".
- **Observer**: timeline rows for `observer.repaired` (kind, reason, target)
  and a banner when the repair budget is exhausted. The observer panel shows
  the last N flight strips without tool args.
- **Goal**: a chip in the composer showing `objective · 2/5 criteria`; clicking
  opens the goals tab. `goal.updated` refreshes it.
- **Build lanes**: a status pill in the subagent bar when the session has an
  active lane ticket; the lanes tab is the full view.
- **Memory**: an indicator when the current turn injected memories; the memory
  tab shows what was used.

New UI components must ignore unknown event types and unknown fields (the
existing reducer already does; keep it that way).

## Compaction row (shipped)

One compaction is **one row**, never two. The timeline folds every source that
reports a compaction — the `session.compaction.suggested|started|ended|failed`
events, `session.inbox.enqueued|delivered|cancelled` for the same `inboxID`, and
the durable snapshot of pending inbox rows plus a surviving `compaction` message
row — into a single record per session
(`session-ui/src/timeline/compaction-state.ts`, `foldCompaction`).

- **Phases:** `suggested | queued | running | done | failed` (plus the implicit
  `none`). At most one of them is live per session; a compaction row is inserted
  after the active turn and ahead of undelivered input, matching the TUI.
- **Deterministic fold.** The reducer never reads the clock: every signal
  carries its own `at` from the event's `created`, signals are sorted by
  `(at, stage, inboxID)`, and a signal older than the record is dropped. Replaying
  the same event sequence always yields the same row, and an event that
  overtakes a snapshot cannot move the phase backwards.
- **Explanatory trigger.** Each row states why it is there, from the
  authoritative `trigger` (not from the legacy `reason`): `guard` → context
  ceiling reached, `overflow` → provider context overflow, `manual` → requested
  by the user or a tool, `observer` → the observer suggested it, `command` →
  `/compress`. Unknown or absent triggers say the server did not report a
  reason rather than guessing.
- **Token context.** When present, the row shows the estimate against the
  trigger or ceiling (`estimateTokens`, `triggerTokens`, `ceilingTokens`) and,
  after a completed run, before/after sizes (`beforeTokens`, `afterTokens`).
- **"Compact now".** Only the `suggested` phase offers the action; it posts the
  same compact route as `/compact` and the row then becomes `queued` from the
  server's own event, not from optimistic local state.
- **The queued badge retires deterministically** on `session.inbox.delivered`,
  `session.inbox.cancelled` or a `session.compaction.started` carrying the same
  `inboxID`. Because the server now emits `delivered` for a consumed compaction
  row, the badge no longer depends on a snapshot diff, which is what produced a
  badge that outlived its run and a "queued + running" pair.

`CompactionQueued` is the single live row type; the durable `compaction` message
row renders only once the run is finished (`SessionCompactionMessage`), so a
running compaction is never also shown as a notice.

## Session queue strip (shipped)

Durable visibility for queued `user` and `synthetic`/peer rows, and exactly-once
chronological promotion.

- **Why an explicit hydrate exists.** `session.created` completes the
  `session.pending:<id>` sync key so the racy first read is skipped, and
  completion is permanent. A session created in the same tab therefore never
  read its durable inbox through a plain `pending.sync`, so the strip stayed
  empty while `GET /api/session/:id/inbox` returned the rows.
  `session.pending.hydrate(sessionID)` (`packages/client/src/solid/data.ts:1713`)
  invalidates the key and then syncs; it coalesces with an in-flight sync, so a
  reconnect or a second controller does not duplicate the read. The composer
  calls it once on mount (`session/composer/queue.ts:202`).
- **Which rows the strip owns.** `queued()` keeps `delivery === "queue"` items
  of type `user` or `synthetic` (`queue.ts:191`), and reordering is disabled for
  the whole strip while it holds a row it cannot reorder (`queueReorderable`,
  `queue.ts:31-33`). Peer (`synthetic`) queue rows are **no longer the strip's
  job**: they render in the main timeline with Send now / Cancel (see *Peer
  messages in the timeline*), and the strip is only mounted for root sessions.
  What remains strip-owned is the user prompt queue: edit, undo, steer and
  drag-reorder.
- **The panel never hides a hydrated row.** `SessionQueuePanel` seeds `shown`
  once at construction and mirrors later changes through a deferred effect, so a
  panel that mounted before hydration had `live()` rows and an empty `shown`.
  The rendered list is `queuePanelRowIDs(shown(), live())`
  (`queue-panel.tsx:25,42`): `shown` keeps closing rows in their old slots, and
  live rows the effect has not mirrored are appended in queue order.
- **Promotion is exactly-once and in place.** `session.inbox.delivered` removes
  the pending item and, when the row is already rendered, keeps it where the
  reader sees it (promotion is not a new arrival); otherwise it inserts at the
  chronological slot (`insertChronological`, `data.ts:518-524`), never at the
  tail. The server promotes before publishing `session.inbox.delivered` and
  promotes an inbox item once ([17](17-interfaces.md)); a replayed delivery does
  not duplicate the row.

Browser proof (built Playwright, 2026-11-25): queued user prompt visible in the
strip, delivered in place, replay idempotent, chronological order kept
(`e2e/verify/queue-delivery.spec.ts:58`); queued synthetic/peer row visible and
still visible after `page.reload()`
(`e2e/verify/startup-scroll-harness.spec.ts:121`); strip at 320 and 390 px with
zero horizontal overflow (`:254`).

## Older-history loading intent (shipped)

`shouldLoadHistory` (`session/timeline/virtualizer.tsx:150-164`) is the single
gate every page request passes:

| intent | loads older history? |
|---|---|
| `restore`, `correction` | never |
| `navigation` (hash / deep link) | yes |
| `bootstrap` (short viewport) | once, then never |
| `user` | only when `!pinned && scrollTop < historyTopThreshold` (`:53`, 200 px) |

An upward wheel, touch or key gesture at the top asks for the older page from
the gesture itself (`handleListWheel`, `virtualizer.tsx:995-1015`; touch `:1018`;
keys `:1107-1125`), not from the resulting scroll event, because the
virtualizer's own corrections also emit scroll events and would spend the flag
first. The gesture unpins with `allowShort`, so a timeline too short to scroll
can still page in above the reader, and a stale `userScrollIntent` is cleared
when the gesture cannot move the viewport — so a later programmatic write (hash
seek, restore) can never page history. `loadOlder` re-checks the same gate and
dedupes per session key (`session/timeline/interaction.ts:252-291`).

Browser proof: a programmatic scroll/anchor correction issued **zero** older
requests, and a real wheel gesture at the top loaded older
(`startup-scroll-harness.spec.ts:156`, assertions at `:233` and `:241`). Unit
gate `scroll-intent.test.ts` + `virtualizer-restore.test.ts` 16/0. Not proven in
a browser: the follow-on content-visibility assertions (Prompt 23 at `:243`,
Prompt 11 at `queue-delivery.spec.ts:203`) and tab-away/back offset restore
(`mobile-agent-queue.spec.ts:85` returned 0). Both stay open; see
[24](24-ui-performance.md).

## Mobile sheets, keyboard and touch targets (shipped)

- **Escape and focus return.** `MobilePanelDrawer` attaches a capture-phase
  `keydown` listener only while open (`listenForEscape` / `closeMobilePanel`,
  `shell/mobile-panel-drawer.tsx:27,46`). It ignores non-Escape keys and IME
  composition but deliberately does **not** bail on `defaultPrevented`: an
  earlier document handler (composer, command menu) calling `preventDefault()`
  must not make a modal sheet undismissable. Close hands focus back to the
  opener on a microtask, because hosts unmount the sheet in the same tick under
  `<Show when={open()}>` and corvu's `finalFocusEl` restore never runs; the
  effect has no `defer` for the same reason (it mounts with `open === true`).
  `agent-drawer.tsx:40-48` routes its close button, overlay dismiss and Escape
  through that one path. Browser proof: `mobile-agent-queue.spec.ts:141` (sheet
  hidden after Escape, trigger focused).
- **Keyboard inset.** `KeyboardInsets` publishes `--keyboard-inset` from
  `visualViewport` and counts coverage only above
  `KEYBOARD_MIN_COVERAGE = 100` px (`runtime/platform/keyboard.ts:8,27,44`; publish at `:64`);
  while the keyboard is up it pins `--safe-area-inset-bottom` to `0px` so the
  home indicator and the keyboard are not both reserved (`:64-68`). The composer
  dock reserves `calc(0.75rem + var(--keyboard-inset, 0px))`
  (`src/index.css:83-85`) and `#root` uses `100dvh` in standalone mode (`:68-79`).
- **Touch targets.** Under `@media (max-width: 640px), (pointer: coarse)` every
  queue row, queue action, agent-tree row/button/search and subagent-bar control
  is at least 44 px, and rows wrap instead of overflowing
  (`src/index.css:89-164`); below 360 px the widest labels drop first (`:166`).
  Browser proof: `mobile-agent-queue.spec.ts:160` (44 px), `:113` at 320 and
  390 px (fit, and the composer survives the keyboard shrink).

## Models tab

The tab is the model **policy control plane**: it decides which models the main
agents and each subagent may use and in what order, keeps free-text notes about
models, surfaces temporary unavailability, and holds `models.favorites` (which
the chat picker boosts). Chat-picker visibility is `!models.hidden[ref] &&
providerConnected` — the selected agent's chain and `favorites` only **order** it,
never filter it (`providers/models/policy.ts:70-81`); this is not a
picker-configuration screen.

Page `settings/models/models.tsx` with the `settings/models/api.ts` client and the
pure helpers in `settings/models/chain.ts`. It is the only writer of the `models`
config block: every control persists through `PUT /api/config/models` with only
the key it changed (`chains` for a per-agent chain, `chain` for the global one,
`notes` for a note, `hidden`/`favorites` for the toggles), and nothing here writes
browser storage except the provider-fold preference. `agentNotes` is never written:
it is read-only legacy rendered as a badge.

### Left column — catalog

- One collapsible group per provider id, **collapsed by default**. The header is
  a real button showing the provider id, the model count and a chevron, with
  `aria-expanded`; it toggles on click and on Enter/Space.
- The fold state persists (`Persist.global("settings.models.providers")` +
  `ModelProvidersSchema`) and survives a reload. "Expand all" / "Collapse all"
  rewrite every group at once.
- Search filters by `[name, id, providerID, ...variants]` and force-expands every
  matching group; zero matches render an explicit empty state instead of a blank
  list.
- A row shows name, variants, cost (already merged with `models.pricing`), a note
  indicator, the favorite star (`favorites`), the eye toggle (`hidden`) and an
  availability badge when the registry reports the model unavailable (failure
  kind plus a relative "until"). Clicking a row focuses it for the notes editor.

### Right column — agent policy editor

1. Agent selector: a `<select>` with `<optgroup>`s "Primary agents", "Subagents"
   and "System roles", fed by `GET /api/agent` (`{id, name, mode, hidden, model}`).
   Primary/subagent groupings exclude `hidden` agents; the third group lists them
   (`compaction`, `title`, `summary` when reported hidden) plus the role ids that
   never appear in `/api/agent` (`SYSTEM_ROLE_NAMES = ["observer", "scribe"]`,
   `settings/models/models.tsx:190,253-258`), because all of them resolve a chain.
   Hidden roles are badged as system roles and are not treated as agents anywhere
   else, so no ghost rows appear. The empty value means the global chain.
2. Selected agent card: its `mode`, its pinned `agents.<id>.model` (read-only,
   with a hint that a chain overrides it) and the effective chain
   (`chains[agent] ?? chain`) with its length against the 16-entry cap.
3. Ordered chain list: one row per entry with index, name, reference and note
   preview, plus move-up, move-down and remove buttons. The empty state
   distinguishes "this agent follows the global chain" from "no chain configured".
4. Add-model search: filters the catalog by `[name, id, providerID, ...variants]`;
   an already-chained reference is rendered as "already added" and disabled
   rather than filtered away, and an explicit empty state replaces a silent empty
   box.
5. Notes: one inline `models.notes[ref]` editor on the chain row plus the catalog
   note indicator — both write `models.notes`, committed on blur or Enter
   (`saveNote`/`saveNoteFor`, `settings/models/models.tsx:479-491`, `:944`, `:1034`).
   There is no per-agent note editor: `models.agent_notes` is read-only legacy
   rendered as a badge (`models.tsx:458-467`, `:1013`).
6. Health: a read-only list of `registry.modelHealth` entries (reference, kind,
   relative "until") followed by the `registry.keyHealth` rows (credential axis);
   see [Key health on the Models tab](#key-health-on-the-models-tab-shipped-state).
7. Per-model quota (`quota.models.<ref>`, `quota.default`), `reserve_percent`,
   `window_hours` and the usage summary live in one `Collapsible` section *below*
   the policy editor, collapsed by default.

Writes: a successful `PUT` refetches the registry and re-renders from it. `400
InvalidRequestError` (`invalid_model: <ref>`) is rendered inline on the offending
row and the whole write is discarded (the server wrote nothing). There is **no
restart banner** — `PUT` answers `x-opencode-config-reloaded: models` and the
policy applies to the next spawn/turn — only an error banner.

Removed behavior: model visibility/favorites used to be a browser-persisted Solid
store (`useGlobal().models`, `runtime/server/runtime.tsx:131-183`,
`runtime/server/persistence.ts:55-72`). The server `models.hidden` /
`models.favorites` lists are now the source of truth for this tab and for the
chat picker.

### Providers tab: backup keys (shipped state)

`settings/providers/providers.tsx` keeps the upstream manage-accounts menu, and
every stored credential is one labelled row in it. The menu's radio group is
bound to the active credential (`activeProviderAccount`,
`settings/providers/providers.tsx:316-360`), so selecting another row calls
activation through `accountActions.activate` (`:268-275`) and that row becomes
the primary key.

Three affordances ship on top of that radio group:

- A non-primary row carries a **"Backup"** badge in the radio list
  (`settings.providers.account.backup`, `providers.tsx:357`,
  `runtime/i18n/en.ts:1102`); the primary row carries none, so the badge marks the
  backups rather than the primary.
- A **"Backup"** group below a separator lists every non-primary credential, one
  `Make primary` item each (`settings.providers.account.makePrimary`,
  `providers.tsx:367-380`, `en.ts:1103`). Selecting it calls
  `accountActions.makePrimary(account.id)` and does not open the connect flow.
- **"Add backup key"** (`settings.providers.account.addBackup`,
  `providers.tsx:388-395`, `en.ts:1101`) opens the same connect flow as "Add
  account", which appends a new `cred_…` row and makes it active, leaving the
  earlier keys in place as backups.

### Key health on the Models tab (shipped state)

The Models-tab health section renders two lists, not one
(`settings/models/models.tsx:992-1060`): `registry.modelHealth` entries (model
reference, kind, relative "until") and, from the same fetch,

## Model selector

The desktop model dialog (`providers/models/select-dialog.tsx`,
`DialogSelectModel`) lists models under one header per provider, plus
`Favorites` and `Recent`. Every header is a real `<button>` with
`aria-expanded`: clicking it collapses or expands that section. A collapsed
section keeps its header so it can be reopened, and its rows leave the list
entirely, so ↑/↓, Home/End and Enter never land on a hidden model. A non-empty
search force-expands every section (the toggle is disabled while searching),
and the collapse state is per dialog open. `SearchList` exposes this through an
optional `collapsed?: (section) => boolean` prop; without it the component
behaves exactly as before. The mobile drawer (`ModelList`) already collapsed
providers through `ProviderModelSections` and is unchanged.

Picker policy: the pure helpers in `providers/models/policy.ts`
(`pickerVisible`, `comparePickerModels`, `effectiveAgentChain`, `favoriteRefs`)
implement

```
visible(m) = !m.hidden && providerConnected(m)
order:      favorites first, then the agent chain order, then name, then ref
```

`models.chain` / `models.chains.<role>` are a **routing preference** (fallback
order), **never** a visibility allowlist: they only decide where a row sorts.
The live config carries a single-entry chain, so the older rule that required
chain membership hid 690 of 692 models. `models.hidden` is now the only
visibility control besides provider connectivity, and the chain (plus
`models.favorites`) affects order alone.
`agentChain = registry.chains[<session agent>] ?? registry.chain` therefore feeds
ordering only; an empty chain means "nothing sorts ahead of the rest". A model
the registry does not list (catalog drift) falls through to the legacy store's
answer, so nothing vanishes on a lagging registry. The `same`-model comparison
drops `#variant`, lowercases and folds `.` to `-`, so a `#high` chain entry sorts
next to the base reference.

Status: wired. `select-dialog.tsx:498-509` calls `pickerVisible` with
`registryModel` / `hiddenSet` / `providerConnected` and passes no chain at all
(`PickerVisibility` has no chain field by design), and `web/dist` carries the
rebuilt bundle.

### Performance budgets

- `GET /api/models/registry` answers < 200 KB and < 150 ms warm for ~700 models.
  `?usage=0` (or `false`) omits the per-model usage rollup for the first paint
  and the Models tab refetches with usage when the usage section opens
  (`RegistryQuery.usage`, `crates/oc-server/src/data/models_registry.rs:781-802`).
  The `quota` pass runs either way, so quota bars stay correct on the sparse body.
- `GET /api/quotas` never blocks on a provider probe: it renders the cached
  snapshot and refreshes out of band. **Shipped** (verified 2026-11-15:
  `refreshing` is `crates/oc-server/src/data/quotas/types.rs:24-25`, set from
  `data/quotas/mod.rs:145`): a cold cache answers HTTP 200 with an empty
  `providers` list, `refreshing: true` is present only while a background refresh
  runs (`skip_serializing_if = "is_false"`), and at most one refresh is in flight.
  `?refresh=true` and `POST /api/quotas/refresh` are the blocking paths
  (`data/quotas/mod.rs:189`).
- The Models and Quotas tabs paint within 300 ms of data arrival: no full-list
  re-render on every keystroke; the initial render is capped/virtualized.

## Data flow additions

- The `createData` reducer keeps unknown event types and fields inert; the
  session agent panels subscribe separately (`session/agent-panels/agent-events.ts`
  for `observer.repaired`, `goal.updated`, `lane.*` and `subagent.peer.message`),
  so no panel event has to be a reducer case.
- Settings and panel data use `solid-query` with `staleTime: 30_000` and
  `refetchOnMount:false` unless a live event stream is absent; the subagent tree
  is the documented exception (`refetchOnMount:true`, `staleTime: 2_000`) and the
  observer budget keeps a 15 s poll (`agent-queries.ts:66-70,173-174,200-204,226-227`).
- All writes are optimistic only for toggles; config writes invalidate
  `config.get`.
- No new global store; scope by server + directory as `ServerScope` does.
