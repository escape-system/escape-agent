# 13 — Web UI

The web client is `../opencode/packages/app`: SolidJS + Vite 8 + Tailwind 4 +
`@tanstack/solid-query` + `solid-js/store`. `packages/web` is the docs site and
is not served. The Rust server serves the built app from the same origin.

## Serving contract

- `GET /` and every non-API GET/HEAD → `index.html`, `no-cache`.
- `_assets/**`, `icons/**` → immutable 1-year cache; missing → 404 `no-store`.
- `/api*`, `/auth/*`, `/openapi.json` never fall back to HTML.
- `sw.js`, `registerSW.js` → `no-cache`.
- Non-GET/HEAD on a page path → 405.
- `X-Content-Type-Options: nosniff` always; no CSP header is emitted yet (the
  build does not write `web/csp.json`).
- `web/dist` is read from disk per request (`OC_WEB_DIST` / `--web-dist`; default
  `<cwd>/web/dist`). It is not embedded with `rust-embed`, so replacing the
  directory takes effect without a restart.
- No compression for SSE or static assets (no `tower-http` compression layer).

## Build pipeline (vendored, reproducible)

`opencode-rust/ui/` contains:

```
vendor/opencode/       # editable MIT source snapshot (app + workspace closure)
UPSTREAM               # version/provenance of the snapshot
patches/               # provenance of the four UI patches (already applied)
build.ps1 / build.sh   # frozen install, vite build, copy + verify dist
verify-dist.mjs        # fails on placeholders/missing assets
```

`ui/vendor/opencode/packages/app` is the frontend source. Edit
`packages/app/index.html` for the HTML entry, or `src/**`/`packages/ui`/
`packages/session-ui` for TSX/CSS, then run `./build.ps1` (PowerShell) or
`./build.sh` (Git Bash). The script runs `bun install --frozen-lockfile`, builds
`@opencode/app`, replaces `opencode-rust/web/dist`, and verifies that
`index.html` has no `%OPENCODE_` placeholders and that every referenced asset
exists. `web/dist` is served from disk by `oc-server`; no Rust rebuild or
embedding is involved. `OC_UPSTREAM` can point at a different **already
patched** checkout.

The four patches under `ui/patches` are kept for provenance and re-vendoring;
the vendored tree already contains them, so the build does not apply patches
(and is therefore idempotent). Updating the snapshot is documented in
[`ui/vendor/README.md`](../ui/vendor/README.md).

## New settings surfaces

Existing tabs: `general, appearance, notifications, shortcuts, projects,
workspaces, providers, models, extensions, servers, experimental, about`
(`src/settings/route.ts`). Add five **per-server** tabs (visible only when a
server is selected):

| Tab | Contents | Backing |
|---|---|---|
| `memory` | search/list/add/forget; scope badges; importance; auto-scribe toggle; storage size | `GET/POST/DELETE /api/experimental/memory`, `PATCH /api/experimental/config` |
| `goals` | active goal, criteria + evidence links, rounds/stalls, history; pause/cancel | `GET/PATCH /api/experimental/goal` |
| `observer` | enable, model, digest model, thresholds, budgets; live flight strips; repair log; manual check | `GET /api/experimental/observer`, `POST /check`, `GET /repairs` |
| `subagents` | default model/agent, max depth, allow spawn, sibling toggle, per-agent overrides; live tree | `GET/PATCH /api/experimental/config`, `GET /api/experimental/subagent/tree` |
| `lanes` | lanes, queue depth, running tickets, priorities, cancel; per-lane concurrency | `GET /api/experimental/lane`, `POST /lane/:id/{order,cancel}` |

Plus:
- `project-lsp.tsx` (workspaces) gains live status, RSS, restart, and
  diagnostics count from `GET /api/lsp`.
- The extensions page shows MCP server status (`connected/needs_auth/failed`),
  plugin inventory, and sidecar state.
- `Config.Patch` is extended with `observer`, `goal`, `subagents`, `memory`,
  `lsp_install`; the settings pages write through it (one write path, config
  documents remain the source of truth). The UI only writes keys the server
  advertises in `Config.Info`.

Wiring points (exact files):

| Need | File |
|---|---|
| Tab id | `settings/route.ts` (`SettingsServerTab`, `serverTabs`) |
| Icon/label | `settings/pages.ts` |
| Nav + body | `settings/shell.tsx` (`serverTabs`, `<Tabs.Content>`) |

## Session and agent UI

- **Subagent tree**: a collapsible panel in the session header showing
  parent/children/siblings with agent, model, depth, lane, status, elapsed vs
  `expect_seconds`. Clicking a node navigates to that session (existing child
  route + breadcrumb).
- **Sibling chat**: a drawer on a child session, listing messages from siblings
  and a composer that calls `POST /api/experimental/subagent/:SID/message`.
  It is visually distinct from user messages (peer badge).
- **Observer**: timeline rows for `observer.repaired` (kind, reason, target)
  and a banner when the repair budget is exhausted. The observer panel shows
  the last N flight strips without tool args.
- **Goal**: a chip in the composer showing `objective · 2/5 criteria`; clicking
  opens the goals tab. `goal.updated` refreshes it.
- **Build lanes**: a status pill in the subagent bar when the session has an
  active lane ticket; the lanes tab is the full view.
- **Memory**: an indicator when the current turn injected memories; the memory
  tab shows what was used.

New UI components must ignore unknown event types and unknown fields (the
existing reducer already does; keep it that way).

## Escape Agent brand layer

The fork is branded in the vendored app without touching server contracts:

| Surface | File |

| About | `settings/about/about.tsx` (version, MIT, fork attribution, notices) |

Design rules: glass surfaces are translucent with `backdrop-filter` and neutral
white hairlines; gold is reserved for brand, focus, selection and primary
actions. Panels do not add gold borders. Upstream layout, transcript, tools,
composer, permissions and routes stay untouched; the added hooks are
`home-grid`, `home-sessions-toolbar`, `home-session-group-header` and
`home-projects-title`.

Timeline and titlebar defaults that follow the brand: reasoning rows start
expanded (`defaultSettings.general.timelineDetail`), and an untouched compact
preset is migrated to visible reasoning; session tabs keep a visible frame,
close affordance and gold busy spinner.

## End-user readiness (live Playwright)

The suite in `packages/app/e2e/escape-agent/` runs against a live server; it does
not start a fixture web server. It blocks service workers so the tested bundle
is the deployed `web/dist`.

```sh
cd ui/vendor/opencode/packages/app
# optional: point at the local Chromium if the Playwright cache version differs
ESCAPE_CHROMIUM="C:/Users/<user>/AppData/Local/ms-playwright/chromium-1208/chrome-win64/chrome.exe" \
  bun run test:e2e:escape

# optional password/connect screen:
ESCAPE_AUTH_URL=http://127.0.0.1:4097 ESCAPE_AUTH_PASSWORD=secret \
  bun run test:e2e:escape
```

Coverage: branded static assets + `server.connected` SSE, centered home hero and
glass panel, new-session wordmark/composer, existing session tab frame/busy
spinner + single message surface, mobile layout without overflow, and the
password connect screen. Result on 2026-10-31 against `127.0.0.1:4096` and a
password server on 4097: **6/6 passed**.

## Data flow additions

- Use the existing `createData` reducer; add cases for `observer.*`,
  `goal.updated`, `memory.updated`, `lane.*`, `subagent.peer.message`.
- Fetch new settings data with `solid-query`, `refetchOnMount:false` and
  `staleTime: 30s`, like the rest of the app.
- All writes are optimistic only for toggles; config writes invalidate
  `config.get`.
- No new global store; scope by server + directory as `ServerScope` does.

## What we do not change

- The transcript renderer, tool renderer, composer, permissions/form modals,
  file tree, terminal and routes stay upstream. The fork brand layer is the
  theme plus `escape/GlobalStyles.jsx`, the wordmark, and the connect/about
  screens; panels and settings pages remain additive.
- Existing routes and URL scheme stay; new pages use the existing `tab`/
  `subtab` query params.
- The app still works with zero new endpoints (features render as disabled or
  hidden when the server reports no capability).
